# 架构设计文档

## 1. 系统架构概述

帽子学做饭采用**前后端分离**的架构模式，前端使用 React Native + Expo 实现跨平台（Android/iOS/Web），后端使用 NestJS 提供 API 服务。

## 2. 架构分层

```

│  │ Android │  │   iOS   │  │   Web   │                  │
│  └─────────┘  └─────────┘  └─────────┘                  │
```

## 3. 后端模块设计

### 3.1 模块划分

| 模块 | 职责 | 依赖 |
|------|------|------|
| `Auth` | 注册、登录、Token 刷新、退出 | Users, JWT |
| `Users` | 用户 CRUD、个人资料、偏好设置 | Prisma |
| `Cuisines` | 菜系信息 CRUD | Prisma |
| `Recipes` | 菜谱 CRUD、搜索、分类、步骤 | Prisma |
| `AI` | 食材识别、菜谱推荐、步骤生成 | HttpModule |
| `Community` | 帖子、评论、点赞、收藏 | Prisma, Users |
| `Upload` | 文件上传、图片处理 | 本地/OSS |
| `Common` | 公共装饰器、过滤器、拦截器 | - |

### 3.2 技术决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 后端框架 | NestJS | TypeScript 原生、模块化、企业级架构 |
| ORM | Prisma | 类型安全、Migration 管理、开发体验好 |
| 认证方案 | JWT + Refresh Token | 无状态、适合移动端和 Web |
| 参数验证 | class-validator + DTO | 声明式验证、与 NestJS 深度集成 |
| 缓存策略 | Redis | 推荐结果缓存、会话管理、限流 |
| API 规范 | RESTful | 简单通用，后续可扩展 GraphQL |

```
frontend/src/
├── app/                    # 页面路由（Expo Router 文件路由）
│   ├── _layout.tsx         # 根布局
│   ├── index.tsx           # 首页
│   ├── (auth)/             # 认证相关页面组
│   │   ├── login.tsx
│   │   └── register.tsx
│   ├── (tabs)/             # 底部 Tab 页面组
│   │   ├── home.tsx        # 首页推荐
│   │   ├── cuisines.tsx    # 菜系学习
│   │   ├── camera.tsx      # 拍照识别
│   │   ├── community.tsx   # 交流圈
│   │   └── profile.tsx     # 我的
│   ├── recipe/
│   │   └── [id].tsx        # 菜谱详情
│   └── post/

│   ├── ui/                 # 基础 UI 组件
│   ├── recipe/             # 菜谱相关组件
│   ├── community/          # 社区相关组件
│   └── ai/                 # AI 相关组件
├── hooks/                  # 自定义 Hooks
├── stores/                 # 状态管理（Zustand）
├── services/               # API 请求服务
├── utils/                  # 工具函数
└── assets/                 # 静态资源
```

### 4.2 状态管理

使用 Zustand 进行轻量级状态管理：

| Store | 职责 | 持久化 |
|-------|------|--------|
| `authStore` | 用户认证状态、Token | ✅ |
| `userStore` | 个人资料、偏好设置 | ✅ |
| `ingredientStore` | 冰箱食材列表 | ✅ |
| `recipeStore` | 当前查看的菜谱缓存 | ❌ |
| `communityStore` | 社区动态缓存 | ❌ |

### 4.3 网络请求

使用 Axios 封装请求层，统一处理：
- 请求拦截：注入 Token
- 响应拦截：统一错误处理、Token 自动刷新
- 请求取消：页面切换时取消未完成请求

## 5. 安全设计

### 5.1 认证流程

```
[客户端] → 登录请求 → [服务器]
                           ↓
                    验证用户凭据
                           ↓
              生成 Access Token + Refresh Token
                           ↓
              ← 返回双 Token ←
              
[客户端] → 携带 Access Token 请求 API
              → Token 过期 → 用 Refresh Token 获取新 Token
              → Refresh 也过期 → 重新登录
```

### 5.2 安全措施

| 措施 | 实现 |
|------|------|
| 密码加密 | bcrypt（12 轮加盐） |
| Token 安全 | Access Token 短时效（2h）+ Refresh Token 长时效（7d） |
| 接口限流 | Redis 计数限流（throttler） |
| SQL 注入防护 | Prisma 参数化查询 |
| XSS 防护 | Helmet 中间件 |
| CORS 配置 | 白名单限制 |
| 文件上传 | 类型白名单 + 大小限制 + 重命名 |

## 6. 性能优化

| 场景 | 策略 |
|------|------|
| 菜谱列表 | 分页查询 + Redis 缓存热门数据 |
| 推荐结果 | 缓存相同食材组合的推荐 |
| 图片 | WebP 格式 + 懒加载 + CDN（后期） |
| 搜索 | MySQL 全文索引 + 食材反查表 |
| API 响应 | 压缩 + 字段筛选 |
